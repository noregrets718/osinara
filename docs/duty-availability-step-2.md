# Шаг 2. Доступность жильца на дату

## Результат шага

Функция `getDutyAvailability` получает проверенные данные дома, ID жильца
и дату. Она возвращает доступность утром и вечером, основание результата
и признак применения индивидуального исключения.

```ts
getDutyAvailability(data, "r04", "2026-11-09")
// {
//   residentId: "r04", date: "2026-11-09",
//   morning: true, evening: false,
//   basis: "shift_night", exceptionApplied: false
// }
```

Это вымышленный жилец из примера с ночной сменой: утром он доступен,
вечером — нет. Конкретные значения берутся из `rules.availability`.

## Файлы

| Файл | За что отвечает |
| --- | --- |
| `agent/lib/duty-scheduling/duty-availability.ts` | Расчёт доступности и оснований |
| `agent/lib/duty-scheduling/duty-availability.test.ts` | Матрица доступности, исключения и граничные случаи |
| `agent/lib/duty-scheduling/duty-data.ts` | Общая проверка запрошенной даты и тип состояния дня |
| `scripts/show-duty-availability.ts` | Таблица доступности всех жильцов в терминале |

В предыдущем шаге `parseDutyData` проверяла даты внутри загруженных записей.
Теперь `parseDutyDate` использует ту же схему для даты запроса: строка
`2026-02-30` не должна попадать в расчёт.

## Порядок расчёта

```text
проверить дату и найти жильца
  → проверить границы проживания
  → определить рабочий/выходной день по календарю
  → выбрать строку матрицы по графику или загруженной смене
  → применить индивидуальное исключение
  → вернуть новый объект результата
```

1. Дата должна существовать и иметь формат `YYYY-MM-DD`. Неизвестный ID
   жильца — ошибка запроса, а не обычная недоступность.
2. День заселения включается. День выезда уже исключается. Например,
   при `inactiveFrom: "2026-11-10"` последний возможный день — 9 ноября.
3. Запись `calendarOverrides` имеет приоритет над обычными выходными.
   `isDayOff: false` делает конкретную субботу рабочей.
4. У жильца 5/2 выбирается рабочий или свободный день. У сменного работника
   ищется запись ровно на эту дату; цикл за пределы таблицы не продолжается.
5. Для сменного выходного общий календарь определяет, какую строку брать:
   выходной в будний день или выходной в выходной день.
6. Исключение меняет только явно указанный период. Второй период сохраняет
   значение основного графика.

## Почему используется `??`

```ts
morning: exception?.morning ?? base.morning
```

`?.` позволяет обратиться к полю, даже если исключения нет. `??` берёт
основное значение только при отсутствии указанного значения. Явное `false`
сохраняется: «недоступен» — полноценное решение владельца. Оператор `||`
здесь ошибочно заменил бы `false` основным значением.

## Основания и неизвестная доступность

`basis` показывает, откуда взялся результат: например, `shift_night`
для ночной смены или `five_two_workday` для рабочего дня 5/2.

Отдельные основания:

- `missing_shift` — на дату нет смены. Оба периода закрыты до уточнения.
- `not_yet_resident` — дата раньше заселения.
- `departed` — наступила дата выезда или более поздняя дата.

Исключение не восстанавливает отсутствующую смену и не отменяет границы
проживания. Для исправления владелец должен уточнить исходные данные.
`exceptionApplied` показывает, что исключение конкретного жильца на дату
было учтено; исключения другого человека или дня не применяются.

Авторизация владельца будет проверяться при сохранении данных через инструменты
агента. Эта функция принимает уже проверенный снимок и не изменяет его.

## Дата и часовой пояс

Дата запроса уже обозначает календарный день дома. Она не является моментом
времени, который нужно переводить между часовыми поясами. UTC в вычислении
дня недели используется только для независимости от настроек сервера.
Одна и та же строка `2026-11-09` остаётся понедельником при разных настройках
часового пояса дома.

## Как посмотреть результат в VS Code

Из корня проекта:

```sh
node --import tsx scripts/show-duty-availability.ts 2026-11-09
```

Команда выведет таблицу с вымышленными жильцами: ID, имя, доступность,
основание и применение исключения. Например, у Тестова будет «Да/Нет»
из-за ночной смены, у Условной — «Нет/Да» из-за отсыпного.

Проверь соседний день:

```sh
node --import tsx scripts/show-duty-availability.ts 2026-11-10
```

В примере смены загружены только на 9 ноября: на 10 ноября у сменных
работников появится «Смена не загружена», а у жильцов 5/2 останется обычный
рабочий день. Свой файл можно передать третьим аргументом после даты.

Тесты обоих шагов:

```sh
npm test -- agent/lib/duty-scheduling/duty-data.test.ts agent/lib/duty-scheduling/duty-availability.test.ts --maxWorkers=1
```

Следующий шаг — определить объекты уборки на выбранную дату: ежедневные
работы и чередование второго/третьего этажей. Назначения людей и нагрузка
добавляются после этого отдельными изменениями.
