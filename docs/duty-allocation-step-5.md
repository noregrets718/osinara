# Шаг 5. Совместное распределение исполнителей

## Результат шага

Функция `prepareDutyDraft(data, history, date)` соединяет предыдущие шаги:
объекты на дату, доступность людей и историю нагрузки. Возвращает локальный
черновик с исполнителями, периодами, основаниями выбора и незакрытыми местами.

Для вымышленного примера на 9 ноября формируется полный график: пять объектов,
шесть разных исполнителей. Столовая получает совместную пару в одном периоде.

## Почему недостаточно брать первого кандидата

Представим два объекта: первый допускает утро или вечер, второй — только утро.
Анна доступна утром и вечером, Иван — только вечером.

| Способ | Гибкий объект | Утренний объект | Заполнено |
| --- | --- | --- | --- |
| Последовательно брать первого | Анна | Никого | 1 место |
| Рассматривать назначения совместно | Иван вечером | Анна утром | 2 места |

При выборе для первого объекта нужно учитывать последующие задачи.
Новая функция может отменить предварительный выбор и переназначить человека.

## Файлы

| Файл в `agent/lib/duty-scheduling/` | Назначение |
| --- | --- |
| `duty-matching.ts` | Точный подбор независимых мест с дневными ограничениями и критериями |
| `duty-allocation.ts` | Совместные группы, общий поиск, сборка черновика и объясняющих показателей |
| `duty-matching.test.ts` | Проверки переназначения, стоимости и сравнение с полным перебором |
| `duty-allocation.test.ts` | Пары, нехватка людей, общий результат и ограничения |

`scripts/prepare-duty-draft.ts` показывает черновик в терминале.
Для вызывающего кода основная функция одна — `prepareDutyDraft`.
Ей нужны уже проверенные снимки `parseDutyData` и `parseDutyHistory`.

## Как выбирается результат

Главная цель — максимально возможное число заполненных мест с соблюдением
ограничений. При равном числе мест сравниваются суммарные показатели назначений
по порядку из `rules.priorities`:

1. Сумма прежней нагрузки выбранных исполнителей.
2. Сумма показателей последних дежурств: более ранние даты предпочтительнее.
3. Сумма показателей последней уборки соответствующих объектов.

Даты превращаются в число календарных дней от начала учёта; отсутствие записи
даёт `0`. Каждый следующий критерий используется только при равенстве предыдущих.
При полном равенстве применяется детерминированный порядок ID и периодов.
Имена, порядок жильцов в таблице и порядок объектов не меняют выбранных назначений.

Используются сами показатели, а не сумма мест кандидатов в отдельных рейтингах:
разница между нагрузкой 0 и 100 существеннее разницы между соседними позициями.
Показатели относятся к истории перед черновиком: сам черновик статистику не меняет.

## Как устроен подбор независимых мест

Внутри `matchDutySlots` строится сеть возможных назначений:

```text
начало → жилец → объект → конец
```

- Связь с жильцом ограничивает число его назначений за день.
- Связь «жилец → объект» допускает максимум одно назначение этого человека
  на этот объект, даже если дневной предел больше единицы.
- Связь от объекта ограничивает число нужных исполнителей.
- У выбора человека есть вектор показателей нагрузки и давности.

Алгоритм последовательно добавляет назначения с наименьшими показателями.
Обратные связи позволяют отменять прежний выбор и перестраивать его, как
в примере Анны и Ивана. Метод поиска пути Беллмана — Форда учитывает эти
обратные связи. Работа продолжается, пока дополнительное место заполнить нельзя.

Сложность сети скрыта внутри модуля: вызывающий код передаёт требования,
кандидатов и оставшиеся дневные возможности, а получает выбранные назначения.

## Совместная группа

Для объекта с `samePeriod: true` и несколькими исполнителями проверяются
возможные полные группы отдельно для утра и вечера. Каждый участник группы
должен быть доступен в общем периоде. Один человек не заменяет двух участников.

После выбора группы оставшиеся места решаются подбором из предыдущего раздела.
Проверяется и вариант оставить группу незаполненной: иногда это позволяет
закрыть больше мест на других объектах. Все допустимые варианты сравниваются
по общим целям, а не только по качеству самой пары.
Ветви, которые уже не могут улучшить найденный результат, безопасно пропускаются.

Совместная группа либо заполнена полностью, либо получает ноль назначений.
У независимого объекта с несколькими исполнителями допустимо частичное
заполнение: оставшиеся места явно отмечаются. Начальная столовая — совместная группа.

## Что находится в черновике

- Дата и версия правил.
- Период учёта и окно нагрузки.
- Требуемые, заполненные и незакрытые места.
- По каждому объекту — исполнители, периоды и причина незакрытых мест.
- По назначению — сохранённый зачёт, место кандидата в рейтинге, нагрузка
  до назначения и даты последних дежурств.
- `missingShiftResidentIds` — кому не хватает смены на дату; это проблема данных,
  которую владелец сможет уточнить.

Человек может оказаться не первым в рейтинге отдельного объекта, потому что
другой кандидат нужен на ограниченной задаче. Черновик сохраняет реальные
показатели выбора для дальнейшего объяснения владельцу.

`canApprove` означает только допустимость полноты по настройке
`allowIncompleteSchedules`. Он не является подтверждением владельца.
Сохранение версий, личное подтверждение и публикация добавляются последующими шагами.

## Лимит поиска

Число сочетаний больших совместных групп может быстро расти. По умолчанию
действует вычислительный лимит `50_000` состояний. Разработчик может передать
`{ maxSearchStates: ... }` четвёртым аргументом.

Если лимит исчерпан, функция выбрасывает `AGENT_DUTY_SEARCH_LIMIT`.
Она не возвращает найденный промежуточный вариант как доказанно лучший график.
При нормальном завершении поиск даёт максимальное заполнение и оптимальные
суммарные критерии для поддерживаемых ограничений.

## Проверка в VS Code

Из корня проекта:

```sh
node --import tsx scripts/prepare-duty-draft.ts 2026-11-09
```

На вымышленном примере итог — «Мест: 6. Назначено: 6. Не закрыто: 0».
Проверь соседнюю дату:

```sh
node --import tsx scripts/prepare-duty-draft.ts 2026-11-10
```

Смены на 10 ноября не загружены: люди со сменным графиком исключаются,
появляются незакрытые места и список недостающих смен. Ограничения автоматически
не смягчаются. После даты можно передать пути к своим данным и истории.

Тесты всех шагов:

```sh
npm test -- agent/lib/duty-scheduling --maxWorkers=1
```

Кроме отдельных сценариев, тесты сравнивают подбор с независимым полным
перебором на 64 малых сетях и на 64 сочетаниях доступности трёх людей.
Это проверяет оптимальность на разных сочетаниях связей и периодов.

Следующий шаг — сохранение черновиков, версий графиков и оснований выбора.
