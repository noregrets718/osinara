# Шаг 3. Объекты уборки на дату

## Что теперь умеет программа

Функция `getDutyObjectsForDate` получает определения объектов уборки и дату.
Возвращает объекты, которые нужно убрать в этот день, и общее число мест
для исполнителей. Имена исполнителей появятся на шаге распределения.

```ts
const result = getDutyObjectsForDate(data.objects, "2026-11-09");
// result.objects: столовая, первый этаж, второй этаж, прачка, администрация
// result.requiredSlots: 6
```

Всего объектов в настройках шесть. На эту дату нужен один из чередующихся
этажей, поэтому в результате пять объектов. Мест шесть: два в столовой
и по одному на остальных объектах.

## Новые файлы

| Файл | Назначение |
| --- | --- |
| `agent/lib/duty-scheduling/duty-day-objects.ts` | Выбор объектов на дату и подсчёт мест |
| `agent/lib/duty-scheduling/duty-day-objects.test.ts` | Проверки циклов, границ дат и групп |
| `scripts/show-duty-day-objects.ts` | Таблица объектов для просмотра в терминале |

## Три операции в функции

```text
objects.filter(...)   → оставить объекты, нужные в эту дату
       .map(...)      → собрать отдельные требования к исполнителям
       .reduce(...)   → сложить число мест
```

- `filter` перебирает массив и оставляет элементы, для которых условие истинно.
- `map` создаёт новый массив результатов. Здесь он сохраняет ID, название,
  число исполнителей, допустимые периоды, совместность и зачёт нагрузки.
- `reduce` собирает одно значение из массива. Здесь это сумма `people`.

Определения объектов сначала проходят `parseDutyData` из шага 1.
Дата запроса проходит общую `parseDutyDate` из шага 2.

## Как работает цикл

У объекта задана периодичность `everyDays` и, при необходимости, дата начала
`anchorDate`. Для уборки через несколько дней начальная дата обязательна.

Пример второго этажа: `everyDays: 2`, `anchorDate: "2026-11-09"`.

| Дата | Дней от начала | Нужна уборка |
| --- | --- | --- |
| 7 ноября | До начала цикла | Нет |
| 9 ноября | 0 | Да |
| 10 ноября | 1 | Нет |
| 11 ноября | 2 | Да |
| 13 ноября | 4 | Да |

Проверка `elapsedDays % everyDays === 0` означает, что число прошедших дней
делится на интервал без остатка. `%` — оператор остатка от деления.
До начальной даты действует отдельная проверка: цикл не продолжается назад.

У третьего этажа дата начала — 10 ноября. Поэтому в начальном примере он
чередуется со вторым. Можно изменить интервал и дату в данных; функция
не содержит названий этажей и не фиксирует интервал в два дня.
Если задать одинаковые начальные даты обоим этажам, они попадут в один день:
чередование является начальной настройкой, а не обязательным ограничением программы.

Ежедневный объект без начальной даты включается на любую корректную дату.
Если начальная дата явно указана и для ежедневного объекта, уборка начинается
с неё и продолжается каждый день.

## Почему считаются календарные дни

Нельзя вычитать только номера дней месяца: после 30 ноября идёт 1 декабря.
Функция использует полные даты и разницу между полуночами UTC. Это учитывает
месяцы, годы и 29 февраля, а переходы локальных часов не создают дробных дней.
Дата уже обозначает день дома; перевода момента времени между часовыми поясами нет.

## Пара в столовой и число мест

Столовая сохраняется одной группой с `people: 2` и `samePeriod: true`.
В ней остаются оба допустимых периода — утро и вечер. Функция не превращает
эту группу в два независимых назначения. При распределении понадобится найти
двух человек с общим доступным периодом. Для одиночного исполнителя условие
одного периода не добавляет отдельного ограничения.

`requiredSlots` считает места, а не уникальных людей. При начальном правиле
«одно назначение в день» шесть мест требуют шести разных исполнителей.
Число мест не уменьшается из-за отсутствия людей: это позволит владельцу
увидеть незакрытые места на шаге распределения.

Результат содержит новые объекты и отдельные массивы периодов. Входные
настройки не изменяются. Типы `Readonly` и `readonly` помогают TypeScript
заметить попытку изменить результат в коде; это проверка типов, а не заморозка
объекта во время выполнения JavaScript.

## Проверка в VS Code

Из корня проекта:

```sh
node --import tsx scripts/show-duty-day-objects.ts 2026-11-09
node --import tsx scripts/show-duty-day-objects.ts 2026-11-10
```

На 9 ноября будет второй этаж, на 10 ноября — третий. В обоих случаях
итог: «Объектов: 5. Мест для исполнителей: 6».
После даты можно передать путь к своему JSON вместо вымышленного примера.

Тесты этого шага:

```sh
npm test -- agent/lib/duty-scheduling/duty-day-objects.test.ts --maxWorkers=1
```

Они проверяют начало цикла, чередование этажей, ежедневные работы, другой
интервал, границы месяцев и года, високосный день, пустой результат,
совместную группу и сохранение входных настроек.

Следующий шаг — история нагрузки и порядок кандидатов: окно в 30 дней,
давность последнего дежурства и чередование объектов между людьми.
