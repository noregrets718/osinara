# Шаг 7.1. Чтение Google Sheets и предпросмотр

## Что добавлено

Входные данные дежурств теперь можно получить из ячеек Google Sheets.
Новый модуль сопоставляет столбцы, проверяет данные и показывает отличия
от предыдущей загрузки: добавленные, изменённые и удалённые записи.

Это первая часть шага 7. Она готовит проверенный снимок и предпросмотр.
Запись в Google, сохранение конфигурации источника, подтверждение загрузки
владельцем и команды Telegram ещё не подключены. Чтение настоящей таблицы
с реальными жильцами не выполнялось; разработка использует вымышленные данные.

Пример: у жильца `r01` изменилась фамилия. Предпросмотр содержит одну
изменённую карточку с прежним и новым значением. Он не считает человека новым
и не переносит назначения на другого жильца: связь определяется постоянным ID.

## Движение данных

```text
личный чат владельца
  → проверка актуальной роли по базе
  → существующее подключение Google и проверка выбранного профиля
  → чтение девяти листов одним batchGet
  → повторная проверка роли владельца
  → преобразование ячеек в DutyData и DutyHistory
  → проверка связей и правил
  → снимок, контрольные суммы и изменения для просмотра
```

`batchGet` — способ прочитать несколько диапазонов одним запросом Google.
Он возвращает диапазоны в порядке запроса. Обращения к листам используют
запись A1, например `'Жильцы'!A:Z`: столбцы A–Z указанного листа.
Параметры сверены с [описанием batchGet](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchGet)
и [описанием диапазонов Google Sheets](https://developers.google.com/workspace/sheets/api/guides/concepts).

## Листы начального шаблона

| Лист | Столбцы | Локальный файл шаблона |
| --- | --- | --- |
| Жильцы | ID, Имя, Фамилия, График, Заселение, Выезд | `residents.tsv` |
| Объекты | ID, Название, Людей, Вместе, Периоды, Зачёт, Каждые дней, Начало цикла | `objects.tsv` |
| Смены | ID жильца, Дата, Смена | `workShifts.tsv` |
| Календарь | Дата, Выходной | `calendarOverrides.tsv` |
| Исключения | ID жильца, Дата, Утро, Вечер | `exceptions.tsv` |
| Настройки | Ключ, Значение | `settings.tsv` |
| Доступность | Тип дня, Утро, Вечер | `availability.tsv` |
| Графики | ID, Дата, Версия, Статус | `schedules.tsv` |
| Назначения | ID графика, ID жильца, ID объекта, Зачёт | `assignments.tsv` |

Это начальная структура, а не требование всегда использовать именно такие
названия. В `source.json` задаются имена листов и заголовки для каждого поля.
Порядок столбцов свободный. В первой строке каждого листа нужны все
сопоставленные заголовки; необязательные значения можно оставить пустыми.
Листы с пустыми данными также сохраняют строку заголовков.
Читаются первые 26 столбцов; заголовки для дежурств размещаются внутри них.

Дополнительные столбцы, например будущие контакты жильца, не попадают в
данные расчёта. Они остаются в таблице. В этой части шага нет операций записи.

## Форматы ячеек

- ID и даты — текст. Даты записываются как `2026-11-09`; неоднозначные
  `09.11.2026` и числовые коды дат не угадываются. Для этих столбцов при
  вставке шаблона следует выбрать текстовый формат.
- Имя можно не заполнять, фамилия обязательна. Дата выезда необязательна.
- График: `five_two` — 5/2, `shift` — сменный.
- Смена: `day` — дневная, `night` — ночная, `recovery` — отсыпной,
  `off` — выходной. Даты за пределами загруженных смен не достраиваются.
- Периоды объекта: `morning`, `evening` или `morning,evening`.
- Логические поля: `Да`/`Нет`, `TRUE`/`FALSE` либо настоящие булевы ячейки.
  В исключениях пустое поле периода означает отсутствие изменения.
- Количество людей, зачёт и периоды в днях — положительные целые числа.
- Статусы прошлых графиков: `draft`, `approved`, `cancelled`, `superseded`.
  Строка графика может иметь ноль назначений и всё равно остаётся в истории.

Значения enum вроде `shift` — фиксированные обозначения программы.
Произвольные синонимы здесь не распознаются. Преобразование фотографий и
обычных сообщений владельца в эти данные относится к дальнейшему диалогу агента.

## Настройки и история

На листе «Настройки» десять строк с ключами:

| Ключ | Пример / смысл |
| --- | --- |
| `schemaVersion` | `1`: версия формата данных |
| `timezone` | `Europe/Moscow` |
| `rulesVersion` | `initial-1`: версия правил |
| `weekendDays` | `6,7`: суббота и воскресенье; пусто — нет регулярных выходных |
| `maxAssignmentsPerDay` | `1` |
| `lookbackDays` | `30` |
| `priorities` | `least_duties,longest_since_duty,longest_since_object` |
| `allowIncompleteSchedules` | `TRUE`: разрешить утверждение с незакрытыми местами |
| `historyMode` | `imported`, `zero_start` или `not_loaded` |
| `historyFromDate` | Дата начала учёта; пусто только для `not_loaded` |

Матрица доступности хранится отдельно на листе «Доступность»: семь строк
с ключами из `rules.availability` вымышленного примера. У каждой строки свои
утренняя и вечерняя доступность. Неизвестный ключ не игнорируется.

`zero_start` должен быть задан явно; пустая история автоматически его не
включает. Для `not_loaded` дата начала и листы прошлых графиков/назначений
должны быть пустыми. Загруженные графики проверяются на единственную
утверждённую версию на дату, ссылки на жильцов и объекты и повторы назначений.

## Предпросмотр и контрольные суммы

`previewDutySheetImport(source, response, previous?)` — обычная функция:
ей не нужны Google, Telegram и база. Она возвращает проверенные `data`,
`history`, счётчики строк, `changes` и реквизиты прочитанного источника.

У изменения есть раздел, ключ записи, тип `added`/`changed`/`removed`
и значения до/после. Строки жильцов сравниваются по ID, смены и исключения —
по жильцу и дате. Сортировка строк и перестановка назначений внутри
исторического графика не считаются изменениями.

Контрольная сумма источника учитывает конфигурацию и прочитанные ячейки,
в том числе дополнительные столбцы. Сохраняются также номера строк
и суммы сопоставленных ячеек. Перестановка строк может изменить сумму
источника при пустом смысловом предпросмотре — это ожидаемо.

Контрольная сумма фиксирует результат чтения для будущей повторной проверки.
Она сама не блокирует редактирование Google Sheets и не делает будущую запись
атомарной. Проверка конфликтов и подтверждаемая запись — следующая отдельная
часть шага 7.

## Ограничение доступа

`readDutySheet(source, ctx, previous?)` предназначена для будущего серверного
инструмента владельца. Контекст `ctx` создаёт приложение, не модель.
Сначала проверяется личный Telegram-контекст владельца и его актуальная роль
в базе, затем вызывается существующий Google executor. Перед возвратом
результата роль проверяется ещё раз: при отзыве доступа во время чтения
содержимое таблицы не возвращается. Соединение базы не удерживается
во время ожидания Google. Источник содержит
точный `profileRef`; смена подключённого аккаунта требует нового выбора.
Общие Google-инструменты во внешнюю группу не добавляются.

Команда чтения задаётся программой, а не произвольным текстом из таблицы.
Ошибки подключения передаются вызывающему коду без автоматических повторов.
Неполный ответ, другая таблица, другой лист, неверное направление ячеек
или свыше 5000 строк данных на листе останавливают загрузку. Также действует
существующий лимит Google executor: 256 КиБ вывода команды.

## Проверка из терминала VS Code

Из корня проекта:

```sh
node --import tsx scripts/preview-duty-sheet.ts
```

Начало вывода:

```text
Предпросмотр загрузки таблицы. Сохранение не выполнялось.
Жильцов: 10. Объектов: 6. Смен: 8.
История: imported. Графиков: 5. Назначений: 12.
Версия правил: initial-1. Изменений: 48.
```

При первой загрузке все 48 записей и настроек показываются как добавленные.
Сгенерировать файлы для изучения структуры:

```sh
node --import tsx scripts/export-duty-sheet-template.ts
```

В дереве VS Code открой `.tmp/duty-sheet-template`: там девять TSV-файлов
и `source.json`. TSV — текстовые строки с разделителем-табуляцией: их можно
скопировать на соответствующие листы будущей тестовой таблицы. Каталог
исключён из Git, исходный вымышленный пример и генератор входят в PR.

Пример с явным файлом настройки:

```sh
node --import tsx scripts/preview-duty-sheet.ts \
  agent/lib/duty-scheduling/fixtures/sheets-example.json \
  .tmp/duty-sheet-template/source.json
```

После файла настройки можно передать JSON-файл прежнего снимка
в форме `{ "data": ..., "history": ... }`, чтобы увидеть отличия.
В терминале выводятся разделы и ключи; полные значения до/после доступны
в результате функции и проверяются тестами.

## Проверки разработки

Прошли 215 тестов модуля дежурств: 45 новых тестов чтения/предпросмотра,
141 прежний тест расчёта и 29 проверок PostgreSQL. Проверки базы выполнены
на отдельном временном контейнере под ограниченной ролью `osinara_app`.
Также прошли 54 существующих теста Google policy, execution и context,
проверка типов и линтер затронутых TypeScript-файлов, `git diff --check`.
Учебный предпросмотр и генератор TSV выполнены локально.

Настоящие Google-запросы в тестах заменены проверяемым транспортом.
Полная сборка, общая проверка типов и остальные тесты проекта не запускались.
Рабочая установка, рабочая база и реальные таблицы не менялись.
