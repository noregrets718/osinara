# Шаг 7.2. Подтверждённая запись изменений в Google Sheets

## Результат

Добавлен слой записи для будущего инструмента владельца:
подготовить точные правки, проверить личное подтверждение, перечитать таблицу,
отправить один пакет изменений и проверить итог. Попытка хранится в PostgreSQL
и переживает переподключение. Повтор одной операции не вызывает Google снова.

Это код модуля, ещё не команда работающего Telegram-агента. Настоящие таблицы
не менялись: Google в тестах заменён транспортом, который моделирует ячейки,
сбой до записи, сбой после записи и конфликт.

## Пример для владельца

Просьба: «Иван утром 9 ноября недоступен; период нагрузки сделай 14 дней».
После преобразования этой просьбы в структурированные правки модуль готовит:

```text
'Исключения'!A3: "" → "r02"
'Исключения'!B3: "" → "2026-11-09"
'Исключения'!C3: "" → false
'Настройки'!B4: "initial-1" → "rules-<ID операции>"
'Настройки'!B7: 30 → 14
```

Пять конкретных ячеек входят в предпросмотр. Для новой строки исключения
задаются ID жильца, дата и только изменённый период. Пустой вечер означает
отсутствие исключения для вечера. Распознавание самой фразы и показ кнопки
подтверждения добавятся при подключении диалога в шаге 8.

Читатель из шага 7.1 дополнен режимом `FORMULA` и возвратом внутреннего
снимка ячеек. Режим нужен, чтобы формула не была незаметно заменена её
вычисленным значением. Запись поддерживается для сопоставленных полей
без формул; формулы в дополнительных столбцах не изменяются.

Для подготовки предложения будущий серверный инструмент должен читать
именно в режиме формул, чтобы исходная и повторная проверки сравнивали
одинаковое представление ячеек:

```ts
const loaded = await readDutySheet(source, ctx, undefined, { formulas: true });
const proposal = prepareDutySheetChange(source, loaded.response, edits);
```

## Как задаются правки

`prepareDutySheetChange(source, response, edits)` возвращает `input` и `plan`.
Функция ничего не сохраняет и не отправляет. Правка существующей строки:

```ts
{ action: "upsert", section: "residents", key: "r01",
  values: { lastName: "НоваяФамилия" } }
```

`upsert` означает «найти по ключу и изменить; если нет — добавить».
Для новой записи нужны все обязательные поля. Можно редактировать жильцов,
объекты, смены, календарь, исключения, настройки и матрицу доступности.
Один ID операции объединяет до десяти разных строк.

Ключи: ID жильца/объекта; `residentId/date` для смен и исключений; дата для
календаря; ключ настройки или тип дня для матрицы. Менять идентификатор
существующей строки запрещено. Выезд задаётся через `inactiveFrom`.

`remove` разрешён для смен, календаря и исключений. Он очищает сопоставленные
ячейки, сохраняя физическую строку и дополнительные столбцы. Эта команда
не удаляет жильцов, объекты и исторические графики. При любой правке весь
будущий набор проходит `parseDutyData` и `parseDutyHistory`: нельзя сохранить
смену неизвестного жильца, пустое исключение или недопустимые правила.

Если содержимое правил, объектов или часовой пояс изменились, а метка версии
осталась прежней, автоматически добавляется `rules-<operationId>`.
Новая метка также входит в предпросмотр. Её расчёт повторяемый: повторное
построение того же предложения даёт ту же версию.

## Подтверждение и порядок выполнения

```text
точное подтверждение владельца
  → checking: занять операцию в журнале
  → перечитать таблицу и сравнить исходную контрольную сумму
  → заново проверить будущие данные и точный пакет ячеек
  → повторно проверить владельца и подтверждение
  → writing: сохранить план до внешнего запроса
  → один вызов Google values.batchUpdate
  → перечитать таблицу и сравнить данные с ожидаемыми
  → applied
```

`input` содержит ID операции, источник с выбранным Google-профилем,
контрольную сумму исходного чтения и правки. Подтверждение проверяется по
точному вводу инструмента `apply_duty_sheet_changes` в существующей таблице
Telegram HITL. Требуются живой личный сеанс текущего владельца, принятое
нажатие `approve` и отсутствие таймаута. Подтверждение графика дежурств
не даёт права менять Google Sheets.

Контекст владельца формирует сервер; произвольный JSON модели не является
авторизацией. Проверки базы завершаются до сетевых вызовов: соединение базы
не удерживается во время ожидания Google. Итог уже начатой записи сохраняется
даже при отзыве роли; возвращать данные бывшему владельцу запрещено.

## Что именно отправляется в Google

Используется [values.batchUpdate](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/batchUpdate)
с режимом `RAW`. Меняются только ячейки, значения которых отличаются;
таблица целиком не перезаписывается. Даты и ID остаются текстом,
дополнительные столбцы и форматирование не затрагиваются. Новая строка
занимает следующую позицию после прочитанных строк; структурное расширение
сетки таблицы эта команда не выполняет.

Действует существующий лимит проекта: не более 3000 символов в JSON-argv
изменяющей команды. Большой пакет отклоняется до записи с просьбой разбить
изменение. Подтверждённый пакет автоматически не делится и не повторяется.

## Конфликты и ограничение гарантии

Повторное чтение обнаруживает правки после предпросмотра, включая
перестановку строк. При отличающейся сумме запись останавливается.
После записи проверяется весь смысловой снимок дежурств, а не только
сообщение об успехе Google. Неожиданный результат не исправляется автоматически.

Это оптимистическая проверка: предполагается отсутствие ручной правки
в коротком интервале между последним чтением и записью. В описании используемого
метода API нет условия сравнения версии строки. Атомарность самого пакета,
описанная в [ограничениях Sheets API](https://developers.google.com/workspace/sheets/api/limits),
не объединяет наше чтение и запись в одну транзакцию. Если ручная правка
попадёт в это окно и будет затёрта нашим пакетом, последующее чтение может
уже не обнаружить её. Полная защита от такой гонки здесь не заявляется.

Журнал координирует операции этого модуля. Редактирование в интерфейсе Google
и прямые вызовы общего Google-инструмента в эту блокировку не входят.

## Состояния журнала

| Состояние | Значение |
| --- | --- |
| `checking` | Подтверждение принято, идёт проверка перед записью |
| `writing` | План сохранён; внешний запрос мог быть отправлен |
| `applied` | Запись завершилась и ожидаемые данные прочитаны обратно |
| `conflict` | Исходная таблица изменилась; запись не отправлялась |
| `failed` | Ошибка подготовки, доступа или чтения до начала записи |
| `unknown` | Запрос мог сработать, но результат надёжно не подтверждён |

Повтор ID с другими параметрами запрещён. Повтор того же ID возвращает
сохранённое состояние и не обращается к Google. Один источник не получает
две одновременные записи от модуля. Блокировка привязана к ID таблицы,
поэтому смена Google-аккаунта её не обходит. Права на чтение журнала — у текущего
владельца той же семьи; входные данные, подтверждение и итоговый план защищены
от перезаписи триггером базы. Удаление всей семьи удаляет и её журнал.

`unknown`, а также незавершённые `checking`/`writing` после падения процесса
блокируют следующие записи в этот источник. Автоматического повтора,
истечения блокировки или объявления «ничего не произошло» нет.
Контролируемая сверка и разрешение такого состояния владельцем — следующий
небольшой шаг перед включением команды. Читать таблицу по-прежнему можно.

## Проверка в VS Code

Из корня `osinara`:

```sh
node --import tsx scripts/preview-duty-sheet-change.ts
```

Скрипт покажет пять ячеек, новую версию правил и затем:

```text
Режим записи: RAW. Изменяемых ячеек: 5.
После ручной правки: конфликт, запись остановлена.
```

Google и база для демонстрации не нужны. Имена и ID вымышленные.

При разработке прошли 251 тест дежурств: прежние 215 и новые 36
(20 подготовки правок, 15 интеграционных и один проверки режима чтения).
Миграции выполнены на отдельном временном PostgreSQL; проверки журнала
прошли под ограниченной ролью `osinara_app`. Проверены типы и линтер
затронутых TypeScript-файлов, `git diff --check`, локальная демонстрация.

Полная сборка и общая проверка типов всего проекта не запускались.
Настоящие Google-запросы не проверялись. Рабочий агент и его база не обновлялись.
Перед использованием ещё нужны сохранение настройки источника, сверка
неопределённых операций и инструменты диалога владельца.
